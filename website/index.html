An autonomous AI computer that lives on your machine.

Jawa Quant Computer is a local agent operating layer. It browses the web, manages files, runs commands, consults your documents and memory, schedules jobs and calls your favourite LLM — driven from a terminal REPL or a loopback web UI.

Each skill corresponds to a module in src/jqc/skills/ — no generated filler, all exercised by the test suite.

How it works

From a sentence to approved, scheduled actions

  1. Your request, a task

    Type in the REPL or POST to the loopback API — the orchestrator creates a task with runtime and step guardrails.

  2. Plan

    A heuristic planner builds a DAG in demo mode; with a real model, plans are produced and verified as structured JSON.

  3. Execute step by step

    The DAG executor runs steps through skills. Each tool call is classified by risk before it acts.

  4. Permission gate

    Low/medium risk auto-resolve in demo mode; sensitive actions queue for an explicit /approve or web approval.

  5. Verify and retry

    A goal verifier checks the outcome; failing steps retry within the guardrail budget before the task is finalised.

  6. Persist and schedule

    Tasks, steps and jobs are stored in a SQLite WAL database; recurring jobs enqueue new tasks through the same pipeline.

Everything is local by default. The service binds to 127.0.0.1 and the shell/filesystem/browser skills are workspace-scoped. Nothing leaves your machine unless you configure a model provider and approve the specific action.

Architecture

Clear module boundaries inside the jqc package

cli REPL entry→ api loopback FastAPI→ orchestrator planner · executor · verifier→ skills 11 tools | models provider router→ security permissions · approvals · vault→ storage SQLite (WAL)→ scheduler cron jobs
ModuleResponsibility
config.pyPydantic settings, JQC_ env prefix; port 8337, data dir ~/.jawa-quant-computer, runtime guardrails.

storage/SQLite repositories with WAL journaling for tasks, steps, jobs, plans and memory.
scheduler/Once / interval / cron schedule math, timezone aware, persisted jobs that enqueue new tasks.
Safety model

An autonomous computer still asks before it acts

🗝️

Loopback-only network

The API binds to 127.0.0.1. Remote control it only if you explicitly expose it.

📋

Risk-classified approvals

Every tool call is assigned a risk class. Sensitive actions are blocked until an explicit approval, in the REPL or the web UI.

⏱️

Hard guardrails

Max 50 steps and 30 minutes per task, max 4 concurrent tasks, workspace-scoped file and shell access.

🔐

Encrypted secret vault

API keys live in a Fernet-encrypted vault backed by the OS keyring, with a secure file fallback. Secrets are never required in a plaintext .env.

Alpha: the core vertical slice is implemented and smoke-tested (scripts/smoke.py). Expect API churn and sharp edges — that is the point of an early release.
Installation

Run it on your own machine in a few commands

Install from source

git clone https://github.com/honeyamn10-source/jawa-quant-computer.git
cd jawa-quant-computer
python -m venv .venv && source .venv/bin/activate
pip install -e .
jawa-quant-computer --version

Start the REPL

jawa-quant-computer     # interactive terminal agent
/help                   # approve, deny, providers, jobs, skills, tasks…
/quit                   # exit

In demo mode a deterministic mock model answers offline, so the whole system runs with no network and no keys.

Bring your own model. Point JQC_DEFAULT_PROVIDER at an OpenAI-compatible endpoint or your local Ollama server for real reasoning. See src/jqc/config.py for every configuration option.
